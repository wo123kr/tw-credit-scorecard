# 신용점수 운영 점검

## 언제
- 새 신청 배치(CSV)가 들어왔을 때: 점수 매기기 → 점검 → 보고서
- 「이번 달 점수가 흔들렸나」「이 신청자는 왜 기준선 아래인가」「집단별 보정이 어긋났나」 질문을 받았을 때

## 순서
1. 참조가 없으면 `scripts/fit_reference.py` (원래 분석과 같은 분할 · 시드로 학습, `ops/reference/`)
2. `scripts/score_batch.py --batch <csv> --out ops/runs/<이름>` → `scores.csv`(점수 · 구간 · 기준선 위/아래 · 사유 코드 3개 · 피처별 점수)
3. `scripts/monitor.py --batch <csv> --scores <scores.csv> --out ops/runs/<이름>` → `monitor.json` · `report.md`
4. 한 명을 설명해야 하면 `scripts/explain.py --scores <scores.csv> --id <id>`

## 판단 기준 (`references/thresholds.json`, 관례값)
- 점수 PSI: 0.10 미만 안정 · 0.10~0.25 관찰 · 0.25 이상 재검토. 관찰 이상이면 피처별 PSI 로 원인 피처를 짚는다
- 결측률이 참조보다 5%p 넘게 오르면 수집 · 적재를 먼저 의심한다. 학습 때 결측이 없던 피처에 결측이 오면 그 건은 「점수 불가」로 두고 짐작으로 채우지 않는다
- 기준선 미만 비중이 학습 기준(20%)에서 ±5%p 넘게 벗어나면 신청자 구성 변화를 의심한다
- 라벨이 있을 때 AUC 가 검증값(0.757)보다 0.03 넘게 떨어지면 재학습 검토
- 승인자의 실제 연체율이 예측보다 2%p 넘게 다른 집단(n ≥ 200)은 보정 점검 대상

## 지켜야 할 것
- 승인 · 거절 결정을 내리지 않는다. 「기준선 이상 · 미만」과 사유 코드까지만. 결정은 심사 담당자가 한다
- 성별 · 나이는 모형 피처가 아니며 점검에만 쓴다. 보고서에 집단별 수치는 적되 결정 근거로 쓰지 않는다
- 숫자는 스크립트 출력(`monitor.json` · `scores.csv`)에 있는 것만 인용한다. 없는 숫자는 「확인 필요」
- 보고서 글은 `references/report_guide.md` 의 틀을 따른다. 경고가 없으면 없다고 쓴다

## 한계
- 공개 데이터가 한 시점뿐이라 시간에 따른 분포 이동은 실제로 볼 수 없다. `scripts/make_mock_batches.py` 는 검증 데이터를 나눠 모의 배치 3개(안정 · 분포 이동 · 결측 급증)를 만든다. 모의라고 밝힌다
